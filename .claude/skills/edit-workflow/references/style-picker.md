# Style picker (Phase 3a)

Goal: Utpal chooses the visual style by *seeing* it, not by reading style names. He picks one option, mixes two, or brings his own.

## 1. Find a style source

Check the skills available in the session, in this order:

1. **Visual Identity skill** (Utpal's skill holding a library of visual styles with sample visuals). If present, load it and use its styles and their sample images.
2. **Lemo-Opuscar** (`lemo-opuscar` skill) — a library of named film styles (e.g. impasto oil painting, watercolour brush, ukiyo-e, satellite briefing, exploded teardown) with demos. Load the skill, run its setup to get the library, and read its style catalogue for names, descriptions and sample stills or demos. Use it only as a style catalogue here; the production itself still follows this skill's workflow.
3. **Neither available** — build the options yourself from the reference library and general craft knowledge, and make sample visuals (see step 3).

If Utpal says he has a style skill you can't see, tell him it isn't loaded in this session rather than guessing its contents.

## 2. Shortlist 3–5 styles for this story

Choose from the source using the beat sheet and the story type:
- Era fit (past / present / future / mash-up — see `asset-roles.md`).
- Tone fit (mystery, inspiring, news-urgent, playful).
- Pacing fit (a painterly style suits breath/wave; a crisp UI style suits burst/pulse).
- At least one safe option, one bold option, and one unexpected option nobody would assume for this topic.
- Avoid styles that are just a reference creator's fingerprint (see `originality.md`).

## 3. Get visuals for each option

In order of preference:
1. Sample images or demo stills that the style source already provides (free).
2. Free renders made locally, e.g. a still from the style library's tools, or a quick HTML/SVG/Remotion frame of one key shot in that style.
3. Paid samples (Kling text-to-image), **only with Utpal's OK**: state how many images and the estimated credits first. One key shot of this video per style, same composition across styles, so the comparison is fair.

## 4. Present a style board

Show it as a visual page (an Artifact or images sent to him), one card per style:
- Name and the sample visual(s).
- One line on the feel, and why it fits this story.
- What it implies: grade, texture, type, motion character, pacing it suits, and cost/effort (all AI stills vs real UI vs heavy 3D).
- Tag: safe / bold / unexpected.

End with the choices: pick one, mix two (say what from each), or bring your own.

## 5. If Utpal brings his own style

He may give reference images, a reel, a link, a mood or a description. Break it down like a reference (`ingesting-references.md`): palette, texture, lighting, type, motion feel, era signals. Turn it into a short style spec, show him one free mock frame in it if possible, and confirm before moving on. If it's a style worth keeping, offer to save it to the reference library.

## 6. Lock it

Write the chosen style into the visual bible as: style name/source, sample image reference, the locked prompt style suffix, grade, texture, type system and motion character. Every later phase follows it.
